# ActiveTab Evidence Observation

## Purpose

Owns retained browser evidence and selected, content-aware network response inspection.

## Ownership

The observer translates fresh CDP observations into bounded local evidence. The browser session owns target freshness and transport lifecycle; the runtime remains the only authority for effectful operations.

`responseBodyInspector.js` coordinates selected-body inspection and format dispatch. `responseBodyJson.js` handles non-evaluating JSON coercion, repair, parse diagnostics, and structural summaries. `responseBodyFormats.js` owns format-specific scans for markup, YAML, event streams, log-like text, and delimited rows. `responseBodySecurity.js` discovers credential metadata and produces redacted source projections; `responseBodyShared.js` holds shared bounds and primitives. `responseBodyViews.js` converts those interpretations into Markdown and provides byte-addressable sections, blocks, tables, and paging.

`semanticPageCompiler.js` emits semantic-page schema version 3, compiling the current DOMSnapshot and interaction candidates into a bounded evidence-linked page model. Structural labels and relationships retain observed/inferred/unknown status. It classifies only high-signal page shapes (`article`, `tabular_data`, `repeated_content`, `form`, or `navigation`) and otherwise reports `unknown`. `semanticFieldSemantics.js` owns bounded field-role and label inference; the compiler supplies its indexed text reader and remains responsible for evidence and page structure. `semanticCandidateRanking.js` owns local task-term and candidate ranking; the compiler re-exports its public function to preserve existing callers. `semanticControlMechanics.js` owns native control classification and mechanic/readiness descriptions; these remain observations with no operation authority. `semanticDomRelationships.js` owns bounded ARIA references, label associations, frame/document keys, containment, and evidence references; it reads only the supplied shared indexes. Table headers and repeated-record fields carry evidence-linked labels and conservative semantic roles derived from explicit item properties, accessible labels, standard semantic elements, associated `aria-labelledby` or unique `label[for]` references, description-list terms, or stable field-name tokens; camelCase field tokens are split before role matching, while randomized names stay unknown. Repeated sibling microdata scopes with one explicit item type are also compiled as bounded semantic collections, independent of CSS class names. Their visible `itemprop` values retain the exact property name, evidence reference, and explicit observed-label provenance; duplicate properties on one record stay unknown rather than selecting an arbitrary value. Microdata records bind their nested controls to the exact record. This is a semantic observation only: it does not create an extraction capability, prove completeness, or imply control meaning/effect. Label associations are indexed once per snapshot, and a role inferred from an observed label remains `inferred`. Repeated-record collection descriptors also retain exact bounded source-group identity, field source keys, and tags for local extraction binding. Model projections omit those source locators. Roles without sufficient evidence remain unknown. Each control may expose a native interaction mechanic such as `follow_link`, `enter_text`, `choose_option`, or `submit_form`, separately from application operation meaning and effect. These are evidence descriptions, never authorization or proof that an interaction is safe. Page content remains untrusted, visible collection counts never imply completeness, and no inferred control meaning can create an operation or effect grant.
- `semantic/structuredData.js` compiles bounded JSON-LD metadata hints from the already-built document indexes. It receives the compiler's existing text and evidence-reference helpers, performs no extra DOMSnapshot acquisition or index construction, never merges hints into visible records, and does not authorize, verify, or add JSON-LD to model projections.
- `candidateCollector.js` derives controls, headings, frame summaries, ranking inputs, and retained lookup locators from the exact DOMSnapshot and its shared `documentIndex.js` index. It owns candidate identity construction and has no browser or dispatch capability; normal capture and retained lookup continue to use the same candidate and backend-node identity rules.
- `frameCollector.js` captures already-attached OOPIF snapshots, accessibility trees, frame geometry, and bounded scroll targets while preserving exact frame and target identities. `BrowserSession` remains the owner of frame attachment lifecycle; the collector cannot attach targets or dispatch page actions. Capture metrics continue through the same instrumented CDP client and evidence byte budget.
- `frameCoordinates.js` maps rectangles and points through captured affine iframe owner quads. It rejects degenerate or non-parallelogram geometry and has no CDP, session, or action authority.
- `evidenceStore.js` is the only owner of retained evidence entries, byte totals, runtime-record accounting, and eviction. Runtime inspection and capture use its APIs; eviction invalidates dependent response projections before the evidence entry becomes unavailable.
- `runtimeStateInspector.js` performs bounded, read-only CDP path inspection and asks the evidence store to append redacted or explicitly requested values under the existing byte and record limits. It cannot mutate evidence accounting or dispatch browser actions. `evidenceSizing.js` provides the shared UTF-8 JSON byte estimator used by the store.
- `selectedResponseInspector.js` coordinates inspection of one explicitly selected retained request. It receives evidence, the existing session, and cache callbacks from `BrowserObserver`; it only reads that request's response body and cannot issue a new application request or dispatch a browser action.
- `responseProjectionCache.js` owns TTL, LRU order, byte/entry bounds, and redacted response projections. `EvidenceStore` eviction synchronously removes projections for that evidence ID so cached views cannot outlive their source evidence.
- `networkResponseAcquisition.js` describes response-body acquisition eligibility, reported versus unknown size, and the per-session single-flight CDP command. It does not grant caller authority or own evidence. The caller's existing authorization gate remains authoritative; acquisition metadata never claims a hard memory bound.

`documentIndex.js` builds a transient index for one exact immutable DOMSnapshot. During interaction capture, candidate discovery and semantic compilation share the same root and per-OOPIF index objects, so tag, attribute, parent/child, form-ID, visibility, and backend-node indexes are built once per captured document. Extraction discovery passes one exact-snapshot index through table, repeated-record, and pagination scans and reuses it for record resolution. Indexes are never accepted for a different snapshot or frame context. OOPIF snapshots are indexed separately and semantic references retain their frame target and parent-frame identity.

Semantic compilation also builds transient `collectionByRef`, `recordByRef`, and frame-qualified repeated-root lookup maps once after source discovery. Control association uses these lookups plus bounded ancestor walks; it does not rescan every collection and record for each control.

Visible headed HTML tables carry observation-local table and cell evidence references. Their bounded row records bind each visible control to the nearest table and row, including nested and cross-frame tables; those references support semantic association only and do not establish control effects or collection completeness. Model projections include only task-relevant row records and continue to obey the existing page-content egress consent.

`BrowserObserver.capture()` supports `lightweight`, `interaction`, `structural`, and `visual` profiles. Interaction is the default and retains fresh candidates without a screenshot. Lightweight omits DOMSnapshot and AX capture; structural retains them, compiles semantic structure, and skips action-candidate derivation; visual adds an explicitly requested screenshot. Each capture records an epoch across target/document generation, root and total DOM mutation counts, lifecycle and route state, attached OOPIF target/frame generations, and viewport/scroll/device scale. An epoch that changes is marked unstable; unavailable mutation or OOPIF tracking is marked incomplete. `BrowserSession.observe()` retries one unstable epoch once, and the observer exposes no action candidates from a capture that remains unstable or incomplete. Capture metrics use `performance.now()` and report document-index build count/time, candidate derivation, semantic compilation, per-CDP-method request count/total/max latency, evidence bytes, and heap/RSS before and after. Session metrics also record end-to-end `observationDurationMs`, DOM-subscription refresh time and successful target count, and coherence retry count; these include timing and recovery overhead in headless/headed comparisons. Never use a profile without action candidates or a stable coherence epoch to authorize an effect.

Interaction and visual observations include `semanticPage` page shape, regions, forms, collections, controls, and native interaction mechanics. A caller goal may locally rank candidates before the 200-candidate response bound using accessible names, headings, and bounded text from the nearest table row, list item, or article. Matching record context retains all controls associated with that record; this helper text is not returned in the compact candidate projection. Candidates selected within each frame's task scope keep priority during the bounded cross-frame merge. The observation records whole-page and task-scope counts separately. The goal text itself is never retained in the observation or sent by the compiler. For workflow planning, ActiveTab may take one demand-driven interaction observation at a 384-candidate bound when the identified task scope is larger than the initial result but no larger than 384. The semantic compiler preserves the same expanded control bound. If the task scope still exceeds that limit, `scopeCoverage` stays incomplete and downstream synthesis must not claim the omitted targets were considered.

JSON-LD `application/ld+json` blocks are parsed as bounded, local `structuredData` metadata hints with script evidence references. They remain separate from visible DOM collections, do not override conflicting visible values, and are omitted from semantic model projections. Malformed, oversized, or excess scripts are skipped with bounded coverage status; scripts are never executed.

Remote model image input retrieves the screenshot only from the retained evidence entry for the same observation. It must match the target ID, document generation, and viewport before release to the explicitly configured image-capable endpoint. Jev-specific capture may set `prepareForJev:true`; this uses CDP clip scaling to reduce large viewports and never upscales a small image. The evidence keeps the CSS viewport and device scale, while decision telemetry records the actual encoded dimensions, pixel transform, full-viewport crop origin, and digest. Screenshot bytes remain local evidence and never enter telemetry or journals.

## Local Contracts

- Retained control lookup searches only the exact immutable DOMSnapshot indexes and compact candidate summaries stored with one evidence entry. It is read-only, bounded to 500 visited nodes, 20 results, and at most 2 seconds; every result includes its stop reason and `actionAuthorized:false`. It never issues live CDP traversal or creates an action identity.
- Visual hit-test resolution maps one exact CDP backend node from the root or an exact attached OOPIF session into its retained snapshot, then walks at most 16 ancestors to find an already-derived candidate. A captured iframe-owner backend node may continue only through one unambiguous child owner binding. Target, generation, mutation count, frame, snapshot, visibility, disabled state, and hit bounds must match. It returns an advisory identity only and never discovers candidates by live DOM traversal.
- The semantic-page projection contains only bounded controls, meaningful regions, forms, collections, and evidence-linked relationships; it does not expose a generic wrapper tree. Control `aria-controls`, `aria-owns`, and supported label associations resolve to exact same-document evidence references without returning raw DOM IDs. Generic wrappers remain internal traversal structure.
- Inspect only a request explicitly selected from retained network activity. Response retrieval reads the selected CDP response and never issues another application request.
- Selected body inspection is opt-in for trusted local callers. `includeSensitive:true` retrieves one selected body and returns a complete redacted view. Credential redaction is best effort and does not classify every private or personal value.
- `includeCredentialValues:true` is a separate trusted opt-in and requires `includeSensitive:true`. It reveals the complete selected source, including all credential values. The bounded credential metadata points to recognized locations without duplicating raw values. The returned body is not retained in evidence, logs, or task journals. MCP never accepts this option as a caller flag; it can reach it only after an independent operator grant for both the selected body and credential values.
- Selected runtime strings use bounded, UTF-16-safe pages for trusted local callers. `includeSensitiveValues:true` returns the requested value chunk with its total length, offset, completeness flag, and next offset; callers can page the complete value without silent truncation. MCP always disables sensitive runtime values.
- Preserve complete source content. Keep original textual form when it can be redacted safely; use canonical redacted JSON when structure-aware redaction requires it and report that normalization. With the explicit credential-value opt-in, retain the original source and full normalized values. Content-aware interpretation may add repaired JSON, format-specific structure summaries, parse diagnostics, or Markdown presentation, but never omits response content.
- Markdown is a normalized, decomposable display format. Typed parse evidence and body-format analysis remain separate and cannot authorize actions or verify application outcomes.
- Structured JSON is decomposed into bounded nested sections and tables while the complete normalized JSON remains available in redacted or explicitly requested full-value form. YAML uses a conservative line-structure scan unless a full parser is configured; event streams and log-like text receive indexed frame/line diagnostics. Decomposition limits must be explicit and must point back to the complete view.
- CSV/TSV Markdown tables are bounded previews. The Markdown report must also include a complete fenced source block, redacted by default and complete-value only under the explicit local credential opt-in, so rows beyond the preview remain indexed and page-addressable.
- Selected body interpretation admits at most 1 MiB of decoded input, 20,000 lines, JSON nesting depth 64, 100,000 JSON separators, 10,000 delimited records, 256 delimited columns, 2 MiB normalized JSON, and 8 MiB Markdown. Known decoded-size and encoded-transfer overages are rejected before body retrieval; actual size is checked before decoding or parsing. Overages return `status:"over_limit"` with the exceeded budget and never masquerade as a complete result.
- `Network.getResponseBody` returns one complete response result. Selected-view paging starts after acquisition and interpretation. The acquisition policy reports `size_unknown` separately, classifies content as textual/binary/other/unknown, refuses streaming request types, rejects reported overages before the command, and includes measured decoded size afterward. `hardMemoryBound:false` is mandatory: content classification and size metadata do not bound the CDP result. One response-body command may be pending per `BrowserSession`; overlapping inspections return `status:"busy"`. Caller timeout/cancellation ends that caller's wait, while the slot remains held until the underlying command settles or the CDP transport closes/times out.
- A prospective streaming path exists in CDP, but it is not equivalent to on-demand retrieval of a completed response. `Fetch.takeResponseBodyAsStream` requires a response paused at headers and the request cannot then continue unchanged; it must be canceled or supplied a replacement body. `Network.streamResourceContent` must be enabled while the response is transferring and returns any data buffered before streaming was enabled. Do not enable interception or retain bodies for every request as a transparent fix: that would change network timing/handling or collect unselected response data. A future opt-in capture mode needs its own lifecycle, privacy, and page-behavior qualification.
- `npm run benchmark:response-inspection` uses an owned Chrome and a loopback-only fixture. It fixes the page viewport at 1280×720/1× and screen dimensions at 1280×1024 in either mode, then reports browser version, page visibility, startup time, response wall time, Node CPU, and sampled Node/Chrome memory. Set `ACTIVETAB_HEADLESS=1` for headless. Synchronous Node work may complete between samples; measurements are noisy and are not a hard memory or latency guarantee. Compare repeated runs on the same host and report the CDP whole-result limitation.
- Syntax repair is an interpretation with a reported mode and repair list. Failed JSON-like parsing reports safe locations and attempted modes; it must not imply that arbitrary text was repaired into valid JSON.
- YAML block-scalar credentials are redacted in the default selected-body view while retaining safe length and character metadata. The explicit credential-value opt-in preserves the complete original scalar. A block marker and indentation scan are not proof of full YAML validity.
- Markdown is the interoperable display and decomposition layer for complex diagnostics: typed analysis retains the authoritative format, parse mode, evidence, and provenance; Markdown adds navigable headings, tables, complete source blocks, indexed sections, and evidence references. Decomposing a report must preserve a path back to the complete redacted source and its structured analysis.
- Markdown reports expose nested heading relationships and byte-addressable fenced blocks and tables. Trusted local callers can request `view:"markdown"` with an indexed `sectionId` or `blockId`, then page the selection with offsets local to it and a document-relative offset. A section selection includes its nested subsections. A sparse UTF-8 byte-to-character index maps random offsets, and a bounded cursor reuses the prior code-point boundary for sequential pages. Page selection reads from the original report string rather than copying the whole selected subtree. Metrics report indexed lookups, cursor hits, and scanned bytes.
- Repeated pages may reuse a five-minute, two-entry, 18-MiB total in-memory cache of redacted response projections, conservatively weighted for UTF-16 storage and bounded to 17 MiB per entry. The cache is keyed by evidence, target, request, and view; a changed current target makes evidence stale before cache reuse or body acquisition, and evidence eviction clears its projections. Full credential-value and sensitive-URL requests bypass the cache. The cache contains no raw CDP response body, and the returned response remains complete through paging without silently truncating its source.
- `renderStructuredMarkdown` is for already-projected structured diagnostics. It produces bounded nested tables and headings plus a complete fenced data block; the caller remains responsible for selecting a safe/redacted projection before rendering.
- Retained request activity contains bounded timing and transport metadata only. Response headers and bodies are retrieved on demand, not retained in evidence snapshots.
- MCP may return the complete bounded selected response projection with recognizable credentials redacted, including content-aware diagnostics and a decomposable Markdown view. It never releases response headers or sensitive URL data. A separate operator grant is required for raw credential values, screenshots, full form values, and sensitive runtime values.
- The default selected-body view never returns recognized credential values in clear text. For recognized credentials, `credentialDetails` may report field path, credential kind, length, encoding clues, character classes, and JWT header/claim names and types; it never duplicates credential or claim values. The explicit local opt-in reveals them in the complete source view.
- Bounded credential metadata reports when its discovery limit may have been reached. The complete source remains page-addressable, so values beyond the metadata index are still available when explicitly requested. Bound or omit individual derived summaries only with an explicit count or limit indicator.
- Credential redaction applies to recognizable values in structured JSON, text, URLs, markup, form data, tabular data, event streams, and inspectable binary text. Opaque or compressed binary formats cannot be fully classified by text patterns.
- The implementation uses Node.js platform APIs and adds no dependency.

## Work Guidance

- Keep evidence, interpretation, action, and verification results distinguishable.
- Actionable link candidates expose only the derived `opensNewTarget` boolean from the DOM `target` attribute; never project the raw target name into model input or telemetry.
- Add a format adapter only when it improves identification or decomposition without evaluating response content.
- Keep parser errors limited to safe location and repair metadata; never copy unexpected source fragments into diagnostics.
- Treat Markdown and all response content as untrusted data when rendered by downstream tools.
