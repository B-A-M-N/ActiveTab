# Decision Services

## Purpose

Bounded semantic page interpretation and Jev review. These services return evidence-linked annotations and predictions; they never authorize or dispatch browser operations.

## Local Contracts

- The semantic analyzer defaults to FreeInference Production model ID `glm-5.3-flash` through the OpenAI-compatible provider interface. Any configured OpenAI-compatible chat-completions provider/model may fill this same annotation role. The standalone auto planner may share the explicitly configured semantic endpoint/model and accepts `FREEINFERENCE_API_KEY`; remote page evidence still requires the separate `ACTIVETAB_MODEL_ALLOW_PAGE_CONTENT=1` opt-in. At CLI task, staging qualification, API, and MCP startup, authenticated model catalogs determine image support for each configured secondary role; OpenRouter model metadata is also checked for Jev when its credential is configured. Visual requests also require screenshot consent; explicit image-capability settings are used only when catalog metadata is unavailable. Jev images additionally require the explicit experimental opt-in. Default secondary-model retries are one and are charged per physical request against the run budget.
- `OpenAICompatibleProvider.requestStructured()` supports named annotation tasks with explicit JSON Schema, JSON-object, or validated text output; one deadline covers retries, backoff, and streamed response reading. Each inference request carries a generated `X-Client-Request-ID` reused across its bounded retries; the provider returns that ID and total latency for its caller's telemetry. Response bytes are bounded, and cancellation/timeout remain distinct from schema errors.
- Provider capability selection affects response formatting only. It cannot promote the semantic service into an action planner or authorization authority.
- Semantic output may only reference candidates from the exact fresh observation and may not invent task values or executable actions.
- Jev is the built-in reviewer and remains pinned to `typesafe/jev-1.14`; the runtime invokes it at selected consequential or uncertain decision boundaries such as form submissions, privileged operations, and explicit recovery reviews. Unique ordinary navigation and exact-value field entry do not invoke Jev. Credentials load from an explicitly configured `ACTIVETAB_JEV_KEY_FILE`, a working-directory `JEV.txt`, or the owner-only home `JEV.txt`, in that order; environment keys are fallback sources. Credential files must be regular, non-symlink, owner-only files. Missing local credentials, refusal, or provider failure is recorded as an advisory failure and falls back to deterministic policy. Its credential must never appear in events, logs, or receipts.
- Jev output is advisory. It cannot override deterministic policy, grant approval, or prove an outcome. A valid `needs_agent_review` result pauses only that proposed action before dispatch; a Jev refusal, unavailable credential, timeout, or provider error is recorded and falls back to deterministic policy. A `supported` result does not admit the action. Pre-action Jev review requires a meaningful trusted target-role or purpose code and image evidence bound to the exact observation; otherwise record `review_insufficient_evidence` without making a supported/clear prediction. This skip does not grant authority or replace deterministic policy admission.
- Semantic and Jev input fingerprints, typed outputs, model versions, rubrics, usage, failures, and observation/decision IDs are recorded as separate linked events. Structural semantic inputs are captured before the request; if page labels are enabled, their event is excluded from training because those labels are not persisted. Semantic/decision input events, workflow synthesis events, and inference route events record the specific call modality (`text_only` or `text_plus_visual`), derived from evidence bound to that request rather than model capability alone.
- The semantic request sends a bounded projection of observed roles, tags, candidate references, accessible control names, and nearby headings to the explicitly configured OpenAI-compatible endpoint. These labels are untrusted page data and are not stored in telemetry; the event store captures the structural projection and a salted input fingerprint. If labels are enabled for the request, the event is excluded from training export. Form values and URL data remain excluded by the observation contract. Do not use regular expressions or generic text scans as a privacy boundary; enforce typed field allowlists and exact nested schemas instead.
- Remote images are disabled unless the selected route supports image input and screenshot consent (`ACTIVETAB_MODEL_ALLOW_SCREENSHOTS=1`) is enabled. If startup catalog metadata is unavailable, an explicit `ACTIVETAB_MODEL_IMAGE_INPUT=1` declaration can serve as a fallback. Jev image input also requires `ACTIVETAB_JEV_ALLOW_IMAGES=1`. Each image must match the exact observation, target, document generation, and viewport. Persist only its digest and structural metadata; never include image bytes in decision events.
- Image configuration declares provider capability and privacy permission; it does not require pixels on every request. Semantic annotations include an image only when the trusted caller requests `useVisualEvidence`, workflow synthesis includes one only when the caller supplies bound image evidence, and visual Jev services capture only at their selected decision boundary.
- Jev multimodal image and Box input are experimental and route-dependent. The runtime sends the documented `TypeSafe-Danger-Zone-Images: true` opt-in and enforces 280–1568-pixel sides, 78,400–2,458,624 pixels, plus ActiveTab's tighter 1.5 MB image cap. A visual observation requested for an image-capable planner is downsampled through CDP when needed; the event stores source viewport, encoded image dimensions, scaling, crop origin, and digest. Jev remains advisory, and a live qualification proves only that the currently configured endpoint accepted that request.
- `VisualDecisionService` exposes page classification, obstruction detection, visual outcome assessment, and target grounding through the shared coordinator. Calls require an explicitly permitted image bound to the exact observation, target, document generation, and viewport. Results are advisory and never authorize an effect or satisfy an independent verification contract.
- Workflow-plan and visual reviews pass an explicit trusted review kind into Jev. The client validates separate pre-action, outcome, workflow-plan, visual-assessment, and target-grounding states; workflow effects must use the bounded declared effect classes. Box questions require bound image evidence and a paired Noul presence question, and malformed coordinates are rejected without clamping. Target grounding receives only a bounded caller target-role code and can select only among locally observed candidates.
- Workflow-plan reviews carry the synthesized plan SHA-256, typed task-contract hash, trusted capability-catalog hash, source observation ID, exact target and document generation, review-policy version, and a digest of that binding. The reviewed projection includes dependency edges, conditions, and trusted capability purpose/precondition/postcondition codes. `status: reviewed` alone never counts as support: only a `supported` result bound to the current plan, task, catalog, target, and observation revision can suppress duplicate pre-action review; `needs_review` pauses before any browser effect.
- Decision input projections retain the bounded instructions and criteria for the exact versioned question rubric alongside the rubric hash. Image bytes remain outside telemetry.
- Jev transport retries default to zero so one remote review cannot consume most of the shared four-attempt run budget. A caller may explicitly configure a bounded retry count; inference-attempt reservations remain authoritative.
- Workflow planning uses a bounded call policy: only an explicitly `atomic` task with fresh, high-confidence deterministic resolution may avoid remote planning; `unknown` and `compound` task shapes route to the configured secondary model without phrase-matching heuristics. Caller-required application capabilities are omitted from the model catalog unless their exact IDs are bound by typed intent. Jev reviews synthesized plans only for multi-step/consequential plans or when bound visual evidence adds a distinct signal. `inference.route_selected` records each selected provider route before its call; it is telemetry and never grants authority.
- A sole required, fresh, trusted ephemeral observed-read capability for an explicitly atomic task may take a deterministic local planning route. This bypasses workflow synthesis only; field policy, source binding, partial-output verification, and telemetry remain in force. Composite or ambiguous requests still route to synthesis or abstain.
- Use `npm run pretest:secondary` for a live text-mapping provider check, `npm run pretest:secondary-image` for a live one-image secondary-model check, `npm run pretest:jev-visual` for Jev image classification plus paired Noul/Box response validation, or `npm run pretest:multimodal` for the combined provider path. These are protocol pretests with synthetic evidence; they do not qualify an application or browser workflow, execute no browser effects, and never run from `npm test`.

## Verification

Use stub providers in tests. Never call live model endpoints from unit tests.
