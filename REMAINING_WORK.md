# ActiveTab: Remaining Work

Updated 2026-10-17. This is a continuation note for the BrowserAct investigation and ActiveTab implementation. The project is still a prototype; this list is not a parity claim.

## Current verified state

- ActiveTab uses native CDP and an MV3 extension/Native Messaging path. It has no Playwright dependency. Tab control requires an explicit extension Attach action or the documented Chrome remote-debugging consent flow.
- The full suite passes **238 tests, 235 passed, 0 failed, 3 skipped** (`npm run test:headed`). Skipped tests require external access: `ACTIVETAB_VISIBLE_CHROME=1` for the visible-extension integration, `ACTIVETAB_CLOUD_AGENT_ADMIN_TOKEN` for the live Cloud Agent E2E, and `ACTIVETAB_SECOND_PROVIDER_ENDPOINT`/`ACTIVETAB_SECOND_PROVIDER_MODEL` for the Ollama second provider.
- P1-H (visual grounding): `DeterministicPlanner` includes position and size evidence (`visualContext`) with ambiguous candidates, enabling screenshot-free visual disambiguation from bounds already captured in the observation.
- P1-H (infinite-scroll convergence): `NavigationEngine` tracks per-identity scroll convergence; after 3 scrolls of the same identity without new matching candidates, it stops with an explicit `unresolved` status rather than exhausting the full scroll budget.
- P2-D (second inference provider): `OpenAICompatibleProvider` verified against Ollama (`llama3-groq-tool-use:latest`) at `10.9.66.193:11434`; the provider returned a valid stop decision and recorded usage (35 prompt + 11 completion = 46 total tokens). The test skips cleanly when the provider is not configured.
- P2-E stress tests added: concurrent logging stress (20 tasks × 50 writes = 1000 non-interleaved lines verified) and concurrent cancellation stress (10 simultaneous NavigationEngine runs with variable-delay cancellation; all resolve to truthful `canceled` states without partial/fabricated success).
- P1-H (dialog handling): `BrowserSession` now tracks `Page.javascriptDialogOpening` events, exposes `hasPendingDialog` and `handleDialog({ accept, promptText })`, and clears state after handling. Stale-element recovery: `NavigationEngine` detects staleness errors (`no longer exists`, `no longer visible`, `stale document generation`) and retries once with a freshly resolved target without consuming the recovery budget.
- Cloud Agent E2E (`test/cloud-agent-e2e.test.js`): when `ACTIVETAB_CLOUD_AGENT_ADMIN_TOKEN` is set, launches Chrome against the live web UI, discovers pages/controls, collects Cloud Agent admin diagnostics via `CloudAgentDiagnosticAdapter`, correlates browser network events with admin records, and produces an evidence-backed investigation report with status `narrowed`. Verified against a live instance at `10.9.66.193` over SSH tunnel (8 diagnostic sources, 8 usage records, 121 settings definitions, 46 tracked events, temporal correlation, 2/3 evidence-backed investigation checks).
- P0-A remediated: `TestRunner` now implements typed interactions (`click`, `fill`, `select`, `toggle`) through `BrowserSession`, verifies navigation destinations, requires evidence-backed setup preconditions, tracks cleanup obligations, blocks unregistered controlled failures, and rejects oversized workflows instead of silently truncating them.
- P0-B remediated: `BrowserSession.observe()` now exposes `latestEvidenceId`. Diagnostic collectors retrieve network and lifecycle facets by explicit evidence ID and verify non-empty, well-shaped data before reporting success.
- P0-C partial: `registerBrowserDiagnosticSources()` is shared by MCP/API. `ApplicationOperationExecutor` provides a registered, effect-classified operation boundary. Live staging diagnostic qualification is still outstanding.
- P0-D partial: the runner emits typed trace events and correlates diagnostic snapshots to step dispatch events. Stable shared-identifier correlation is available but not yet exercised against live backend records.
- P0-E remediated: Cloud Agent examples are explicitly labeled `"template": true, "executable": false`. The profile loader no longer substitutes placeholder URLs or untyped action descriptions.
- P1-A remediated: discovery now uses `waitForChange` instead of fixed sleeps, protects side-effecting routes, and includes button/menu-item/tabs (not just links) for exploration.
- P1-B remediated: capability-map controls use a SHA-256 composite key including page, context, role, and name. `KnowledgeStore` supports authority/principal-scope composite keys.
- P1-C remediated: `InvestigationEngine` accepts `session` and `testRunner` references. `#reObservePage`, `#checkLoginMarkers`, `#compareControlName`, `#reObserveAfterWait`, `#collectFreshSnapshot`, `#logObservedValue`, and `#reRunStep` now perform actual evidence-backed checks. Report status distinguishes `CONFIRMED`, `NARROWED`, `INCONCLUSIVE`, `BLOCKED`, and `BUDGET_EXHAUSTED`.
- P1-D remediated: assertions use `observation.candidates` (the native observation contract) and return evidence IDs. `diagnostic_source_available` requires collected, usable evidence; registration alone returns UNCERTAIN.
- P1-E remediated: MCP `tools/call` is fire-and-forget so long-running calls do not block status or cancellation requests.
- P1-F remediated: `createMutationAuthorizer()` requires explicit credentials unless `allowUnauthenticated: true` is explicitly configured. All `/v3`, `/v2`, `/v1/test`, and `/output` endpoints require auth for both reads and mutations. Extension origins with valid tokens are allowed; extension origins without tokens are rejected.
- P1-G remediated: `launchDisposableChrome()` accepts a `bootstrapUrl` for runner-owned browser targets, avoiding the test-only about:blank workaround.
- P1-H partial: `DeterministicPlanner` and `NavigationEngine` now support `fill`, `select`, and `toggle` actions in addition to `click`, `scroll`, and `type` (search). Visual grounding and SPA state detection remain unimplemented.
- P2-E partial: remote executor validates response ownership and blocks nested sensitive-field forwarding. Cancellation semantics and concurrent logging race remain untested.
- The REA findings and evidence are in `/home/bamn/rea/experiments/browseract-capability-matrix.md`; architecture, capability gaps, proposed REA integration, roadmap, acceptance criteria, and previous validation records are in `docs/engineering-plan.md`.

## Remaining work, in priority order

1. **Complete P0-C live diagnostic qualification.** The `ApplicationOperationExecutor` and diagnostic source adapters are implemented, but no live Cloud Agent/FreeInference staging diagnostic source has been exercised. Live staging access is required.
2. **Complete P0-D live correlation qualification.** The runner emits typed trace events and correlates diagnostic snapshots to step dispatch events. Stable shared-identifier correlation against live backend records is still required.
3. **Complete P1-H navigation planner.** `fill`, `select`, `toggle`, dialog handling, and stale-element recovery are now supported. Visual grounding, SPA state detection, file interactions, and infinite-scroll convergence remain unimplemented.
4. **P2-B end-to-end integration tests.** Done on 2026-10-17: the E2E vertical now exercises attach, browser discovery, multi-step interaction (Create resource → server-side confirmation), test-run execution, diagnostic collection, controlled failure, investigation with real evidence, cleanup (Delete resource → server-side confirmation), and a qualified report. The fixture server independently tracks resource state, so the test proves what actually happened.
5. **Complete P2-C Cloud Agent staging qualification.** Live staging access is required to create a test-owned connector, execute an MCP tool, retrieve backend diagnostics, and produce a qualified report.
6. **P2-D broader generalization.** Partial on 2026-10-17: second inference provider (Ollama) verified, concurrent cancellation stress (10 simultaneous engine runs) and concurrent logging stress (1000 non-interleaved lines) verified. Still outstanding: multiple Chrome versions, held-out sites, complex forms/frames/virtualized lists, and benchmark metrics.
7. **P2-E secondary runtime gaps.** Done on 2026-10-17: concurrent logging stress (1000 lines, no interleaving) and concurrent cancellation stress (10 simultaneous engine runs, truthful terminal states) are verified. Remote-executor sensitive-value redaction is implemented and tested. Remaining: actual multi-node stress with real peers.
8. **Run the paired BrowserAct SaaS baseline if access is provided.** The hosted Workflow API requires Bearer authentication and a configured workflow ID. No API key was found, so there is no SaaS task result. Use identical authorized task definitions, initial state, failure injections, and independent outcome oracles before reporting any comparison.
