## AT-R03 — Cancellation and terminal-state finality

Legacy API cancellation persists `cancel_requested` before aborting an active worker. A result with explicit pre-dispatch evidence settles as `canceled`; a possibly dispatched or unverifiable result settles as `reconciling`. Terminal task status, output, error, and metadata are immutable, and restart turns an unsettled cancellation request into `reconciling`. Browser cancellation uses the engine's dispatch-certainty result; cancellation after a remote HTTP request is dispatched remains unresolved. Regressions cover pre-dispatch cancellation, cancellation during verification, late metadata updates, API task cancellation, and remote request cancellation. Reconciliation remains a manual/operator workflow; cancellation does not undo an already-dispatched effect.

## AT-R04 — Reattachment dependency rebinding

Run-owned profile-form, observed-search, extraction, visual-decision, deferred-read, and registered-pagination helpers now receive a getter for the current `NavigationEngine` session. Form/extraction verification and visual reads resolve that binding at execution time; a visual observation whose target or document generation no longer matches the current session is dropped. The registered pagination authorizer also checks the current replacement target. `workflow-form-capabilities.test.js`, `visual-decision-coordinator.test.js`, and `workflow-synthesizer.test.js` exercise replacement-session use and stale-target refusal. The existing detached-click regression still proves the action is not replayed.

This closes the demonstrated stale-closure path for the built-in helpers. Custom capability services receive `getSession` and must use it themselves. A real Chrome sequence combining reattachment with a later OOPIF or visual-grounded workflow step remains unqualified; this is not inferred from the unit regressions.

## AT-R05 — Complete observation admission bindings

When a `BrowserSession` supplies its authoritative observation sequence, the executor now requires nonempty evidence identity, exact target and document-generation bindings, stable coherence metadata whose start/end epochs match that target and generation, and the current observation sequence. Missing any binding refuses before input dispatch. `authorized-executor.test.js` covers each missing field and a complete positive control. Existing lightweight observations remain eligible for navigation after the same freshness checks; they still cannot authorize interaction without candidates. Real browser integration remains part of the full headless/private-Xvfb parity run.
